# Race-table identity and key audit — 2026-11-18

Read-only PostgreSQL catalog inspection of production project `rzosrbkyniyedolhkgxo`. Current state, not proven historical baseline.

## Identity
All five `id bigint` columns in `bs_race_events`, `bs_race_entries`, `bs_race_results`, `bs_race_result_entries`, and `bs_ai_predictions` have `attidentity='d'` meaning **GENERATED BY DEFAULT AS IDENTITY**. Their attached sequences are respectively `public.bs_race_events_id_seq`, `public.bs_race_entries_id_seq`, `public.bs_race_results_id_seq`, `public.bs_race_result_entries_id_seq`, and `public.bs_ai_predictions_id_seq`. Identity columns do not necessarily show a conventional `pg_attrdef` expression; the previous absence of column default is **not** evidence of manual ID assignment.

`bsc_results.id` is UUID with `DEFAULT gen_random_uuid()`, not identity.

## Primary keys and uniqueness
- `bs_race_events`: PK(id); **two separate unique constraints** `bs_race_events_race_unique` and `bs_race_events_unique` on (race_date, course_code, race_no).
- `bs_race_entries`: PK(id); unique (race_date, course_code, race_no, boat_no).
- `bs_race_results`: PK(id); unique (race_date, course_code, race_no).
- `bs_race_result_entries`: PK(id); unique (race_date, course_code, race_no, boat_no).
- `bs_ai_predictions`: PK(id); **two separate unique constraints** `bs_ai_predictions_public_unique` and `bs_ai_predictions_race_date_course_code_race_no_character_c_key` on (race_date, course_code, race_no, character_code, timing).

## Foreign keys
- `bs_race_entries_event_fk`: race key -> `bs_race_events`, ON DELETE CASCADE.
- `bs_ai_predictions_race_event_fk`: race key -> `bs_race_events`, ON UPDATE CASCADE ON DELETE CASCADE.

## Replay implications
- Baseline DDL must use IDENTITY, not `bigint` without ID generation or guessed `bigserial`, if targeting today's identity semantics.
- Duplicate same-column UNIQUE constraints exist in production; do not silently deduplicate during a faithful schema comparison. They may have different historical origins and create extra indexes.
- Historical migration chronology still must determine which constraints existed before first migration and which were added later.
- No production writes, Cron changes, paid branches or PR modifications were made.
