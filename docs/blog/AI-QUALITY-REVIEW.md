# AI下書きの品質評価（PHASE 4.9・blog-ai-v11）

AI下書きの品質を、自動の採点表と人の評価表の2つで見ます。どちらも編集者の参考情報です。記事どうしを比べるときは、`docs/blog/AI-EVALUATION.md` の評価表を使います。

- 承認できるかどうかは、これまでどおり「要修正」（blocking）の項目だけで決まります。
- 点数によって自動で承認・公開されることはありません。
- 「要確認」を0件にすること自体は目標にしません。読者にとって分かりやすく、役に立つかを見ます。

## 自動の採点表（編集画面「記事品質の目安（参考）」）

保存済みの版を確認するたびに計算し、画面に表示します。DBには保存しません（`lib/blog/ai/scorecard.mjs`）。

| 観点 | 5点の目安 | 点が下がる主な理由 |
|---|---|---|
| 事実の正確性 | 数値・日付・比較・表がすべて出典と一致 | 出典にない数値・日付、比較・順位・並び順の誤り、表の数値の誤り（いずれも1点）。データにない因果関係、要確認の比較、スタート展示の進入を本番の進入として書く文、過去の1着率を当日の勝つ確率として書く文（4点） |
| 出典の適切さ | データを書いたブロックすべてに出典 | 出典のない数値・比較・事実。取得日時のない収録データを使うときは注記を表示 |
| 重複の少なさ | 同じ内容の繰り返しなし | 同じ事実・特徴・注意書きの繰り返し、注意書きの置き場所、冒頭の数字・比較、表の数字や並び順の再掲、号艇とコースの説明の繰り返し、1着率の定義の繰り返し、導入で書いた基本情報の本文での繰り返し（会話の言い直しはキャラクターの観点だけで数えます） |
| 数字の解説 | 1着率の意味、表、注目したい特徴（2〜3個）をすべて説明 | 特徴の未使用（未使用の特徴を表示）、数字を並べるだけ |
| キャラクターの自然さ | 役割どおりの会話、本文にない視点。短い記事で会話なしも5点 | 本文の言い換え、注意書き・DATA CHECKの理由の言い直し、役割と合わない発言、テーマ外の人物、本文と同じ特徴の確認だけの会話（4点まで） |
| 記事全体の読みやすさ | 分量・構成に指摘なし | 情報量に対して長い、情報のない文、決まり文句、中身のないDATA CHECK、DATA CHECKの項目の重なり |
| 導入とまとめ（blog-ai-v7以降） | 導入の問い、号艇とコースの説明、確認の理由、まとめの発見がそろっている | 導入文なし、導入に問いや発見がない、導入がタイトルと同じ発見、号艇とコースの説明が表の前にない、DATA CHECKに理由がない、まとめに発見がない、まとめが定義の言い直し、表があるのにWARNINGに1着率の注意がない（blog-ai-v8以降） |

- 「平均」は従来の6項目の平均で、PHASE 4.2以降の記事と比べられます。「全項目」は「導入とまとめ」を含めた平均です。
- 「導入とまとめ」は、元データの版が3以上（blog-ai-v7で作った記事）にだけ付きます。それより前の記事は「対象外」と表示し、v7の構成チェックも行いません。
- 出典のない一般論（「〜と言われる」「一般的に」「定説」など）は、全記事で要確認として表示し、正確性を4点にします。「〜とされています」のように出典の事実を伝える言い方は対象外です。
- 会話で、答える側が直前の発言を言い直している場合（`dialogue_echo`）は、全記事でキャラクターの観点から1点減らします。
- タイトル・抜粋・SEO文の比較も本文と同じく検証します。データと明らかに合わない比較は要修正、意味がはっきりしない比較は要確認です。

### 重複の数え方（PHASE 4.5）

- 同じ注意書きが何か所に出ても、注意書きの重複（`repeated_caveat`）は1件だけ数え、繰り返した場所を一緒に表示します。WARNINGの外に1回だけ出た場合は「注意書きの置き場所」（`caveat_misplaced`）として1件です。同じ文で2点減ることはありません。
- 号艇とコースの違いの説明（「号艇別ではなく…」など）が、会話・DATA CHECK・見出し・冒頭・まとめ以外の2つ以上のブロックに出たら `explanation_repeated` として1点減らします。
- 会話がWARNINGやDATA CHECKの理由を言い直している場合（「本番で変わる」「勝つ確率ではない」など同じ考えを含む場合）は `dialogue_repeats_note` として、キャラクターの観点で1点減らします。「下の確認項目で見てみよう」のように参照するだけの会話は対象外です。
- まとめで重要な発見を1〜2個、本文と違う言葉で振り返るのは重複ではありません。冒頭（要点）と見出しが同じ言葉を使うことも重複に数えません。

### PHASE 4.6の変更（常滑v8の実生成から）

- 「決めつけ」は、過去の数字・1着率・集計などについて書いたときだけ「過去の数字だけで判断しない」注意書きとして数えます。「表をコース番号の順だけで決めつけず」のような表の読み方の文は対象外です。
- 1着率の定義（「そのコースから進入した艇が1着になった割合」）を本文で2回以上説明したら `definition_repeated` として1点減らします。まとめ・会話・DATA CHECK、号艇とコースの説明の文は数えません。
- 導入に水質・干満差などの基本情報があり、本文でも同じ基本情報を書いたら `basics_repeated` として1点減らします。導入に基本情報がない場合や、冒頭の要点・まとめ・DATA CHECKは対象外です。
- まとめの締めは、発見が表の読み方にどう役立つかで終え、当日の確認（出走表・進入・展示）に話を戻さないよう、プロンプトで指示します（blog-ai-v9）。

### PHASE 4.7の変更

- 「同じ文の繰り返し」（`repeated_content`）は、集計期間の文字列（「2026/07/01〜2026/09/30」「2026年7月1日から9月30日」など）を同じ語に置き換えてから比べます。期間だけが同じ2文は繰り返しに数えず、期間の書き方だけが違う同じ文は今までどおり指摘します。
- プロンプト（blog-ai-v10）では、「今回の集計期間は〜です」のような期間だけの文を書かず、期間はその期間の数値を最初に書く文に添えるよう指示します。期間の違う数値を同じ文で混ぜません。
- 「24場の基本」の1着率の記事は、水質・干満差を導入の1文に入れ、基本情報のセクションを作りません。水面の記事は、基本情報を最初のセクションにします。

### PHASE 4.9の変更（戸田v10の実生成から）

**並び順の検証（正確性）**
- 「内側から順に並んでいない（ところがある）」「1コースから6コースまで内側から順に高い」「外のコースが内側のコースを上回るところがない」など、表全体の並び順についての文を、公式データと照合します。
- データとはっきり矛盾する文は「比較の誤り」（`comparison_mismatch`、要修正）として承認を止めます。出典が付いていても同じです。本文・タイトル・抜粋・SEO文のどこに書かれていても照合します。
- 「〜とは限りません」「〜じゃない？」のような含みのある言い方や、推量の文は、矛盾していても要確認（`comparison_unclear`）にとどめます。認識できない否定がある文も要確認にします。
- 「内側から順に並んでいるでしょうか」のような問いは、主張として扱いません。「外側のコースでは」のように一部のコースに限った文も照合しません。
- 隣り合うコースの差が0.5ポイント以内のときは、並び順の判断が分かれるため、どちらの主張も誤りにしません。

**データの特徴の追加**
- 「1コースの1着率は半分に届いていない」（`under_half:1`）と、「1着率は1コースから6コースまで内側から順に高い」（`sequence:in`）を加えました。
- 逆転がない場では、これらをタイトル・導入の問い・まとめの発見に使い、その場ならではの記事にします。本文での記述もデータと照合します。

**誤検出の修正**
- 同じ形で別の特徴を述べた文（「1コースが最も高い」と「6コースが最も低い」）は、同じ文の繰り返しに数えません。同じ特徴の繰り返しは、今までどおり「同じ特徴の繰り返し」として指摘します。
- 同じ事実の繰り返しは、数字の境界で照合し（「42.8%」の中の「2.8」は数えない）、システムが作る表は数えません。
- 見出しは、注意書きの置き場所のチェックの対象にしません。
- DATA CHECKに「・」の項目があるとき、「・」のない行は前置き（`data_check_preamble`、読みやすさ）として指摘します。理由のない項目は、今までどおり指摘します。
- 似た記事のチェックでは、別の場の名前だけを含むタイトルを比べません（同じテーマは、どの場でもタイトルの形が似るため）。同じ場の記事は今までどおり比べます。

**プロンプト（blog-ai-v11）**
- 導入の問いとまとめの例文を、その場のデータの特徴に合わせて作ります。常滑の例文を他の場に流用しません。
- 初音の質問は、導入で問いかけた特徴（会話でだけ説明する）についての疑問にします。号艇とコースの違いは、本文とDATA CHECKに任せます。
- DATA CHECKは項目の行だけにし、前置きの文を書きません。会話は、表と特徴を説明するセクションに置きます。
- 「内側から順に並ばない／並ぶ」「半分を超える／届かない」のような表全体の特徴は、データの特徴（readings）にあるときだけ書きます。

### キャラクターの案内役（PHASE 4.7）

| テーマ | 案内役 | 会話の相手 | 会話の形 |
|---|---|---|---|
| 24場の基本：1着率 | 一果 | 逆転（外のコースが内側より上）があればキイナ、なければ初音 | キイナが発見を話す／初音が導入で問いかけた特徴について質問し（PHASE 4.9）、一果が読み方を答える |
| 24場の基本：初音と見る水面と干満差（`water-hatsune`） | 初音 | 一果 | 初音が初心者の疑問を質問し、一果が答える |
| 24場攻略：キイナが気づいた外コースの数字（`outer-kiina`） | キイナ | 一果 | キイナが外コースの発見を話し、一果が読み方を答える（逆転がなければ「内側から順に並ぶ」など） |
| 1人だけのテーマ（水面と干満差、イン逃げ、24場の魅力、キャラクターと巡る〇〇） | 各キャラクター | なし | 会話を作りません。書かれた場合は「会話が多すぎる」として表示します |

- 案内役はトピックの `character_key` で決まり、DBの構造は変えていません。
- 一果が会話にいるときは、一果が説明を受け持ちます。初音は質問、キイナは発見という役割は、案内役でも変わりません（品質検証の「キャラクターの役割」で確認します）。

### 出典IDの誤り（品質の目安とは別）

- AIが `source_ids` に出典ではないID（例：データの特徴 readings の「R2」）を書いた場合、記事を組み立てるときに外し、作成時の確認結果に要修正（`unknown_source`）として記録します（従来どおり）。
- 外したIDは記事に保存されないため、保存済みの版の確認では見えません。編集画面では「作成時の出典IDの誤り（記事品質の目安とは別）」として表示し、承認時に記録する確認結果にも注意（`source_id_error`）として残します。該当ブロックの出典が内容と合っているかを確認してください。
- 承認できるかどうかは、これまでどおり保存済みの版の確認（要修正の件数）だけで決まります。登録されていない出典IDは保存できず、確認でも要修正になります。

### 比較の検証（PHASE 4.3）

- 否定は、その否定が付いた節だけに効きます。「4コースは3コースより高く、内側から順に下がるわけではありません」は4＞3を述べた文として読み、「4コースが3コースより高いわけではありません」は何も述べていない文として扱います。
- 「要修正」になるのは、データと合わないことがはっきりしている比較だけです（集計期間が複数ある場合は、どの期間の値とも合わないとき）。
- 「3コースではなく4コースが…」のように同じ節の前に否定がある比較や、一部の集計期間とだけ合わない比較は「要確認」（`comparison_unclear`）として表示し、承認は止めません。
- 「高い順に…」の並び順も検証します。表がある記事で並び順を文章にしている場合は、表の繰り返しとして指摘します。

## 収録データ（S1）の扱いと確認手順

`lib/stadiumBasicGuide24.js` の収録データには、公式情報と照合した日時の記録がありません。取得日時や確認日を推測で補うことはしません。

- コース別1着率など、数値がテーマの記事では、確認日のないレース時間帯（デイ・ナイターなど）をAIに渡しません。水質・干満差は、当日取得した公式の場データの値を使います。
- 水面がテーマの記事ではレース時間帯を渡し、出典欄に「取得日時 記録なし」、確認結果に要確認（`source_without_fetch_time`）を表示します。
- 公開前に、編集者が次の手順で確認します。
  1. 場の公式サイトや開催日程など、その事実が書かれた公式ページを開く。
  2. 編集画面の「人が追記した事実の出典を登録する」で、確認した事実・出典名・URL・確認した日時・登録者名を登録する。
  3. その事実を書いたブロックの「このブロックの出典」で、登録した出典を選ぶ。
  4. 公式ページで確認できない場合は、その事実を記事から削る。
- 既存の記事と、保存済みの出典記録は書き換えません（再生成した記事から新しい扱いになります）。

## 用語集とDATA CHECKの確認理由（blog-ai-v7、v8で注意書きを分離）

AIは次の文言だけを使って用語を説明し、DATA CHECKの理由を書きます（`lib/blog/ai/glossary.mjs`）。文言を変えるときは、BoatStrikersとして正しいかを人が確認してから変更してください。数字は含めていません。

| 用語 | 説明 | 根拠 |
|---|---|---|
| コース別1着率 | 集計期間の中で、そのコースから進入した艇が1着になった割合。 | BOAT RACE公式の場データ（「コース別入着率」は進入コース別の集計） |
| 号艇（枠番） | レースごとに出走表で決まる、各艇の番号（枠の番号）。 | 一般的な用語説明（公式の場データでも「枠番別コース取得率」として枠番とコースを別に扱う） |
| 進入コース | スタートのときに艇が実際に入った位置。内側から順に番号で呼び、号艇と同じとは限らない。 | 一般的な用語説明（同上） |
| スタート展示 | レース前の展示航走のうち、スタートの様子を見せるもの。展示のときの進入コースが分かるが、本番の進入が同じになるとは限らない。 | **公式資料での追加確認が必要**（展示航走の正式な構成と定義） |
| 集計期間 | 数字を数えた期間。期間が違えば数字が変わることもある。 | 一般的な説明 |

1着率の注意書き（blog-ai-v8）：定義から分け、記事のWARNINGに必ず入れます。AIのWARNINGに含まれていない場合は、記事を組み立てるときにシステムが追記します（元データの版が4以上で、表がある記事）。

> コース別1着率は過去の集計期間の数字で、これからのレースで勝つ確率ではありません。

| DATA CHECKの項目 | 確認する理由 |
|---|---|
| 出走表の号艇と選手 | 号艇と進入コースは同じとは限らないので、まず出走表で各号艇の選手を知る |
| スタート展示の進入コース | 本番の進入を考えるときの参考になる（本番で変わることもある） |
| 展示後の直前情報 | 展示のあとに公開される情報も合わせて見る |
| 当日の水面と天候 | 集計期間の数字には当日の条件が含まれないので、別に確かめる |

- 「本番では変わることもある」はDATA CHECKのスタート展示の項目に、1着率の注意はWARNINGに、それぞれ1回だけ書きます。会話では言い直さず、「下の確認項目で見てみよう」のように参照します。
- 文言の原則：スタート展示の進入を本番の進入と同じものとして書きません。過去のコース別1着率から、当日の勝つ確率や舟券の判断を導きません（「当てはめる」などの表現も使いません）。展開や有利不利も推測しません。
- スタート展示の正式な定義（展示航走の中での位置づけ）は、公式資料で確認してから文言を確定してください。
- 直前情報の具体的な中身（展示タイムなど）は、公式資料で確認できるまで記事で説明しません。現在の文言は「展示のあとに公開される情報」までにとどめています。

## 人の評価表（承認前に5段階で確認）

| 観点 | 確認すること |
|---|---|
| 事実の正確性 | 数字・集計期間・比較を出典欄のリンク先で確認したか。表の6つの数字は公式ページと一致するか |
| 出典の適切さ | 各ブロックの「出典・参考」のリンク先に、そのブロックの事実が載っているか。BoatStrikers収録データの事実は場ページの内容と一致するか |
| 重複の少なさ | 同じ説明・注意書きを2回読まされていないか。会話での再登場が理解を深めているか |
| 数字の解説 | 初心者が「どのコースが高いか」「意外なところはどこか」を説明できるようになるか |
| 導入の引き | 導入文を読んで、続きを読みたくなるか。問いがデータの種明かしになっていないか |
| タイトル | 何が分かる記事かが伝わり、読みたくなるか（テーマ名そのままでないか） |
| 初心者への説明 | 号艇とコースの違いが、表を読む前に自然に分かるか。専門用語が多すぎないか |
| DATA CHECKの理由 | 「なぜ確認するのか」に納得できるか。展開や有利不利の推測になっていないか |
| まとめの印象 | 記事で分かった発見が記憶に残るか。定義や注意書きの繰り返しになっていないか |
| キャラクターらしさ | 一果（データの読み方）・初音（初心者の疑問）・キイナ（外コース・意外な発見）の口調と役割が自然か。必要のない人物が出ていないか、会話がなくても成り立つ記事に無理に会話が入っていないか |
| 記事全体の読みやすさ | 基本情報・データ分析・当日確認の役割が分かれ、最後まで迷わず読めるか |
