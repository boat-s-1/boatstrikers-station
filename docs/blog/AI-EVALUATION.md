# AI記事の評価表（PHASE 5.0）

AI下書きを、自動の採点だけでなく、人の評価と編集者の修正箇所もあわせて比べるための表です。

- 承認できるかどうかは、これまでどおり「要修正」（blocking）だけで決まります。この表の点数で承認・公開が決まることはありません。
- DBには保存しません。自動の値は、ステージングの下書きを読み取り専用で写した固定データ（`tests/blog/_tokonameV*.mjs`、`_todaV10.mjs`、`_todaV11.mjs`）からローカルで計算します。
- 戸田v11の固定データ（`tests/blog/fixtures/toda-v11-staging-20261012.json`）は、ステージングの記事・ブロック・元データ・作成時の確認結果をそのまま写したものです。ステージングの `md5(jsonb::text)` と一致することをテストで確認しています（v10の元データからの再構成ではありません）。
- **自動の評価**（採点表）と、**記事を読んだ編集評価**は分けて記録します。下の「人の評価」は人が記入する欄で、まだ記入されていません。

## 使い方

1. 記事を固定データにしたら、`scripts/blog/ai-evaluation.mjs` の `ARTICLES` に追加します。
2. `node scripts/blog/ai-evaluation.mjs` を実行し、出力された表で下の「自動の評価」を置き換えます（テストで一致を確認しています）。
3. 「人の評価」と「編集者の修正」は、記事を読んだ人が手で記入します。空欄は未評価です。

## 評価項目

| 項目 | 自動の評価（採点表・確認結果） | 人の評価で見ること（1〜5） | 編集者の修正として記録すること |
|---|---|---|---|
| 事実と数値の正確性 | 正確性の点、要修正の件数（比較用記事の表示は除く） | 表・数値・集計期間が公式ページと一致するか | 直した数値・比較の件数 |
| 出典IDの正確性 | 出典の点、作成時の出典IDの誤り（`source_id_error`）、自動出典の件数 | 各ブロックの出典が内容と合っているか | 出典を付け直したブロック数 |
| 文章の重複 | 重複の点と指摘 | 実際に同じ内容を2回読まされたか | 削った文の数、自動の指摘の誤検出・見逃しの件数 |
| 読みやすさ | 読みやすさの点、文字数、ブロック数、平均文長 | 最後まで迷わず読めるか | 言い回しを直した箇所の数 |
| キャラクターらしさ | キャラクターの点、会話の登場人物 | 口調・役割が自然か（一果＝読み方の説明、初音＝初心者の疑問、キイナ＝意外な発見） | 書き換えたセリフの数 |
| 記事としての面白さ | 導入とまとめの点（参考） | タイトル、導入の引き、発見の意外性、まとめの印象 | タイトル・導入を直したか |
| 編集者が修正する箇所 | — | このまま公開できるか（はい／いいえ） | 修正したブロックの数と種類（事実・出典・重複・表現・キャラクター・構成）、かかった時間 |

## 戸田v11の評価（PHASE 5.0）

戸田v11（blog-ai-v11、比較用、ステージング `stadium-basics-toda-course-v11`）について、自動の評価と、記事を読んだ編集評価を分けて記録します。

**自動の評価（採点表）**

PHASE 5.0の文章品質のチェックは元データの版5以降の記事にだけ適用します。戸田v11の元データは版4なので、**戸田v11自体の点数は全項目5点のまま変わりません**。同じ記事を版5の元データで作ったと仮定した場合の評価は次のとおりです（`tests/blog/aiQualityV50.test.mjs`）。

| | 実際の元データ（版4） | 版5として評価した場合 |
|---|---|---|
| 要修正 | 比較用の表示だけ | 比較用の表示だけ（文章品質の指摘で承認は止まりません） |
| 点数（正確性・出典・重複・数字の解説・キャラクター・読みやすさ・導入とまとめ） | 5,5,5,5,5,5,5 → 平均5・全項目5 | 5,5,4,4,3,2,5 → 平均3.8・全項目4 |
| 指摘 | なし | 一果が初音の気づきの言い直し、会話の締めが話題外の案内、定義の言い直し（「各コースから進入した艇の1着率として」）、中身のない締め、「一方」のつなぎ、向きが曖昧な「内側から順に高く」。数字の読み方の説明なし（数字の解説は4点まで） |

**記事を読んだ編集評価**

- Claudeが記事を読んで付けた目安は3.5程度です（PHASE 5.0の設計調査のとき）。人による評価ではありません。下の「人の評価」の表は未記入です。
- 読んで気になった点：上の自動の指摘と同じ6点です。自動の評価（版5として3.8）は、この読み取りに近づきましたが、人の評価で確かめる必要があります。

**模範記事（手書き、AIの生成ではありません）**

blog-ai-v12で求める書き方を手で書いた模範記事は、要修正0件・指摘なしで全項目5点です（`tests/blog/_models50.mjs`）。元データの出どころを分けて記録します。

| 模範記事 | 元データ | 出どころ |
|---|---|---|
| 戸田（初音が質問） | 公式（ステージングv11の元データ、2026-10-12取得） | 実データ |
| 常滑（キイナが逆転を発見） | 公式（ステージングv6の元データ、2026-10-10取得） | 実データ |
| 桐生（初音が「ほぼ同じ」を質問） | 公式（取得済みページの固定データ 2026-10-10 を、実際の処理で元データにしたもの） | 実データ |
| 初音の水面・キイナの外コース（常滑） | 公式（常滑と同じ） | 実データ |
| 浜名湖（逆転と差の小さいコース） | 合成データ（数字は検証用に作ったもの。出典も合成データと明記） | **合成データ（ロジックの確認だけ）** |
| 多摩川（計画の確認だけ） | 合成データ | **合成データ（ロジックの確認だけ）** |

- 戸田の模範記事は「0.7ポイント差」のような計算した数字や「42.8%！」を使わず、3コース（14.9%）と4コース（14.2%）の元の数字を示して「差は小さい」と説明します。
- 合成データの記事で会話や指摘の動きを確かめても、実データでの検証が済んだことにはしません。逆転と差の小さいコースが同時にある場の実データは、まだありません。
- 模範記事は手書きです。blog-ai-v12で実際に生成した記事の評価は、生成の承認後に行います。
