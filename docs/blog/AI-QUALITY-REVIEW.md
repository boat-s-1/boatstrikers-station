# AI下書きの品質評価（PHASE 4.3・blog-ai-v6）

AI下書きの品質を、自動の採点表と人の評価表の2つで見ます。どちらも編集者の参考情報です。

- 承認できるかどうかは、これまでどおり「要修正」（blocking）の項目だけで決まります。
- 点数によって自動で承認・公開されることはありません。
- 「要確認」を0件にすること自体は目標にしません。読者にとって分かりやすく、役に立つかを見ます。

## 自動の採点表（編集画面「記事品質の目安（参考）」）

保存済みの版を確認するたびに計算し、画面に表示します。DBには保存しません（`lib/blog/ai/scorecard.mjs`）。

| 観点 | 5点の目安 | 点が下がる主な理由 |
|---|---|---|
| 事実の正確性 | 数値・日付・比較・表がすべて出典と一致 | 出典にない数値・日付、比較・順位・並び順の誤り、表の数値の誤り（いずれも1点）。データにない因果関係、要確認の比較（4点） |
| 出典の適切さ | データを書いたブロックすべてに出典 | 出典のない数値・比較・事実。取得日時のない収録データを使うときは注記を表示 |
| 重複の少なさ | 同じ内容の繰り返しなし | 同じ事実・特徴・注意書きの繰り返し、注意書きの置き場所、冒頭の数字・比較、表の数字や並び順の再掲（会話の言い直しはキャラクターの観点だけで数えます） |
| 数字の解説 | 1着率の意味、表、注目したい特徴（2〜3個）をすべて説明 | 特徴の未使用（未使用の特徴を表示）、数字を並べるだけ |
| キャラクターの自然さ | 役割どおりの会話、本文にない視点。短い記事で会話なしも5点 | 本文の言い換え、役割と合わない発言、テーマ外の人物、本文と同じ特徴の確認だけの会話（4点まで） |
| 記事全体の読みやすさ | 分量・構成に指摘なし | 情報量に対して長い、情報のない文、決まり文句、中身のないDATA CHECK、DATA CHECKの項目の重なり |

### 比較の検証（PHASE 4.3）

- 否定は、その否定が付いた節だけに効きます。「4コースは3コースより高く、内側から順に下がるわけではありません」は4＞3を述べた文として読み、「4コースが3コースより高いわけではありません」は何も述べていない文として扱います。
- 「要修正」になるのは、データと合わないことがはっきりしている比較だけです（集計期間が複数ある場合は、どの期間の値とも合わないとき）。
- 「3コースではなく4コースが…」のように同じ節の前に否定がある比較や、一部の集計期間とだけ合わない比較は「要確認」（`comparison_unclear`）として表示し、承認は止めません。
- 「高い順に…」の並び順も検証します。表がある記事で並び順を文章にしている場合は、表の繰り返しとして指摘します。

## 収録データ（S1）の扱いと確認手順

`lib/stadiumBasicGuide24.js` の収録データには、公式情報と照合した日時の記録がありません。取得日時や確認日を推測で補うことはしません。

- コース別1着率など、数値がテーマの記事では、確認日のないレース時間帯（デイ・ナイターなど）をAIに渡しません。水質・干満差は、当日取得した公式の場データの値を使います。
- 水面がテーマの記事ではレース時間帯を渡し、出典欄に「取得日時 記録なし」、確認結果に要確認（`source_without_fetch_time`）を表示します。
- 公開前に、編集者が次の手順で確認します。
  1. 場の公式サイトや開催日程など、その事実が書かれた公式ページを開く。
  2. 編集画面の「人が追記した事実の出典を登録する」で、確認した事実・出典名・URL・確認した日時・登録者名を登録する。
  3. その事実を書いたブロックの「このブロックの出典」で、登録した出典を選ぶ。
  4. 公式ページで確認できない場合は、その事実を記事から削る。
- 既存の記事と、保存済みの出典記録は書き換えません（再生成した記事から新しい扱いになります）。

## 人の評価表（承認前に5段階で確認）

| 観点 | 確認すること |
|---|---|
| 事実の正確性 | 数字・集計期間・比較を出典欄のリンク先で確認したか。表の6つの数字は公式ページと一致するか |
| 出典の適切さ | 各ブロックの「出典・参考」のリンク先に、そのブロックの事実が載っているか。BoatStrikers収録データの事実は場ページの内容と一致するか |
| 重複の少なさ | 同じ説明・注意書きを2回読まされていないか。会話での再登場が理解を深めているか |
| 数字の解説 | 初心者が「どのコースが高いか」「意外なところはどこか」を説明できるようになるか |
| キャラクターの自然さ | 一果（数字の読み方）・初音（読者の疑問）・キイナ（外コース・意外な発見）の役割に合っているか。必要のない人物が出ていないか |
| 記事全体の読みやすさ | 基本情報・データ分析・当日確認の役割が分かれ、最後まで迷わず読めるか |
