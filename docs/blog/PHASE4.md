# BLOG PHASE 4 — editor and preview checks

Implemented on `feature/blog-media-platform` without applying the BLOG migration to the production database.

`/admin/blog` uses the existing signed admin cookie in the `/admin` layout. It lists only real BLOG rows from the explicitly configured BLOG Supabase project. With no BLOG verification project it shows the zero-article state and disables mutations. Server routes recheck authentication, the exact same-origin header, and the BLOG-specific read/write switches. Service-role credentials stay server-side and are never sent to the browser.

`/admin/blog/new` creates a draft using `blog_create_draft`. `/admin/blog/posts/[id]` edits the schema-v1 structured document, including optional TEXT, HEADING, POINT, DATA_CHECK, WARNING, QUOTE, IMAGE, CTA blocks. Existing dialogue and other block types are preserved; the grouped dialogue UI belongs to PHASE 5. Up/down controls work by touch as well as mouse. Required publication metadata is checked by the PHASE 1 database function. SEO title/description and noindex are editable; published canonical and structured SEO are scheduled for PHASE 8.

Autosave uses the existing versioned `blog_save_draft` RPC and shows dirty/saving/saved time/error/conflict. Changes are stored in an IndexedDB recovery copy. Only an explicitly requested recovery matching the server version can reapply it. A 409 blocks retries and retains local changes. The bottom bar provides manual save, editing preview, and publication settings. The preview route is authenticated, noindex and uses the editing document. `blog_release` seals the editing revision; `blog_change_state` handles unpublish/cancel schedule. Autosave never changes the published pointer or sealed revision. Scheduled publication still requires the separately configured worker; no production job was enabled.

Media upload requires `BLOG_MEDIA_BUCKET` to reference an already-created **public bucket in the isolated BLOG verification project**, in addition to `BLOG_SUPABASE_URL`/`BLOG_SUPABASE_SERVICE_ROLE_KEY`. It checks the bucket's public setting before upload, only accepts JPEG/PNG/WebP up to 8 MiB and requires alt text. It writes a real public URL to `blog_media` and rolls back the uploaded object if DB insertion fails. Only public media is offered in the editor. No shared race bucket or existing media table is modified. Bucket provisioning and verification environment setup are still required before real uploads can be exercised.

Preview verification checklist: sign into the existing admin account, open `/admin/blog`, inspect narrow iPhone viewport, create a draft only after the isolated BLOG migration and bucket have been tested/applied there, save, preview, test simultaneous edits and 409, publish/rollback only in that isolated environment. Do not use production content/credentials for test records. The zero-article UI and editor shell can be reviewed without the BLOG database. Existing bottom navigation/other site layout is unchanged.
