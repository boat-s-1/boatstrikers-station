# TRINITY SHADOW 初日・保存率監査（2026-09-27）

## 対象と事実

- 本番 `bs_race_events` と `trinity_prediction_snapshots` を読み、締切時刻と `inserted_at` を照合した。
- 12:10 JST の初回正常保存より前に締め切った42レースは導入前として別集計する。
- 15:29 JST 頃の時点で、導入後に締切済みの63レースのうち、52レースに V2 と V3 candidate-01 の2件が保存され、11レースは未保存。片方だけ保存されたレースと締切後保存は0件。
- 未保存11レースの現在の `bs_race_entries` には展示タイム・STが6艇分揃っていた。ただし現在値は後日も更新されるため、締切前に揃っていたという証拠にはならない。

## Vercel実行ログ

- 12:00 JST の実行は4レースで `trinity_scores` の NOT NULL 違反を記録した。12:10 JST の修正版から正常保存を開始した。
- 以後は10分ごとの実行で、保存対象に `no_exhibition`（6艇の展示タイム・ST不足）が毎回記録された。例：12:20 JST は8件の試行中3件保存、5件展示不足。
- 当時のログは見送りレースの識別子を残していないため、未保存11件すべての原因をレース単位で断定できない。`bs_race_entries.updated_at` は同日15:36 JST に一括更新された行があり、現在値の更新時刻から当時の展示ST取得時刻を復元できない。
- 10分間隔と締切3分前の保存限界の組合せでは、締切前に入力が揃っても再試行されない時間帯がある。

## 対応

- SHADOW Cron を2分間隔にして、保存可能な最後の3分に再試行できるようにする。
- 各Cron実行のログにレース識別子と試行結果を含める。今後の未保存は `no_exhibition`、`incomplete`、DBエラー等を個別に追える。
- 管理画面に、締切済み全レースを分母にした、導入後のV2/V3同一入力・締切前ペア保存率と未保存レース一覧を出す。これは入力準備率ではない。
- 片方だけ保存されたレースを後から異なる入力で補完せず、異常として表示する。
- この変更は予想ロジック、候補01の固定条件、公開TRINITY、過去スナップショットを変更しない。

## 再確認

新しい本番配置後、Cronの `attempts` を照合し、翌日の締切済みペア保存率と未保存理由を確認する。展示データが締切前に一度も揃わなかったレースは、後から再生成しない。

## 21:41 JST 追跡調査

- 導入後締切済み114Rのうち100Rが同一入力・同時生成のV2/V3ペア、未保存14R、片方のみ0R。導入前42Rは別枠。
- 福岡2R（12:11締切）は12:00のNOT NULL違反ログに個別識別子があり、12:10の初回正常保存時には締切3分前を過ぎていた。
- 残る13Rのうち11Rは、現在の `exhibition_field_meta` に記録された最後の6艇分展示タイム・STの受理時刻以降、締切3分前までの間に旧10分間隔Cronの実行機会がなかった。旧Cronの時間窓と整合する。受理時刻は更新可能な元テーブルから取得したため、当時の全入力が完成していたとの断定には使わない。
- 津6R（12:56締切）は、現時点の展示項目メタ情報からは12:50の旧Cron時刻までに6艇分が揃っていたように見えるが、旧ログにレース別の見送り理由がなく確定不能。研究用データへは復元しない。

- 9月28日の `bs_race_events` / `bs_race_entries` / 他の調査済み出走ソースは21:41 JSTで0行。過去4日間の `bs_race_entries` の最初の行は各当日00:02 JST付近に作成された。現状の出走表同期では前日夜の予想入力を取得できない。翌日00:02に取得したデータを「前日保存」として扱わない。
- ただし公式BOAT RACEの9月28日開催一覧は9月27日21:22 JSTに更新済みで、[戸田1R出走表](https://www.boatrace.jp/owpc/pc/race/racelist?hd=20260928&jcd=02&rno=1)には6艇分の登録番号、平均ST、全国・当地勝率、モーター・ボート2連率、締切予定時刻が掲載されていた。したがって翌日データ自体が未公開なのではなく、現行同期に前日公開分の取り込みがない。次の作業は公式ページの取得可否・更新時刻・パースと全艇検証、性別の信頼できる参照元、元ページの取得時刻と原文の固定保存を検証すること。`bs_racers`には戸田1Rの登録番号6件が存在せず、過去`bs_race_entries`に残る同選手の性別もNULLだったため、現在の入力で全艇の前日版を保証することはできない。
- `trinity-v3-candidate-01` の条件は引き続き固定。展示不足を見送った際、次回から艇番と不足フィールドをログに追加する。夜間は翌日のイベント件数をログに出す。予想・公開処理は変更しない。
