**HOLD: isolated environment only.** Never execute on production or the unrelated PR #294 branch.

1. Provision/verify a disposable isolated PostgreSQL project and clone only the required schema plus representative result-only fixtures. Obtain explicit approval before paid branch creation if needed.
2. Review candidate SQL; install the unified rows, summary, and recorder functions in that order using a migration in the isolated project. Verify PUBLIC/anon/authenticated cannot EXECUTE and service_role can.
3. Ensure no V2 recorder or scheduler runs concurrently. Verify 2026-11-13 seeded results-only rows exist and no fixture events for those race keys.
4. Run `completeness-v3-isolated-smoke.rollback.sql` as a privileged dedicated test role. It invokes the real recorder twice, asserts count/uniqueness/first_detected_at stability, then ROLLBACKs. A failed assertion aborts the transaction; issue explicit ROLLBACK in the session.
5. In a separate isolated test, validate repaired-event alert resolution, partial repair persistence, actual notification delivery after COMMIT, and rollback behavior. Do not treat pg_notify inside a rolled-back transaction as delivered.

7. Preserve PR Draft/HOLD until these checks and a coordinated V2→V3 cutover and rollback plan pass.
