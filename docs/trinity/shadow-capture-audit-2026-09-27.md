# TRINITY SHADOW 初日・保存率監査（2026-09-27）

## 対象と事実

- 本番 `bs_race_events` と `trinity_prediction_snapshots` を読み、締切時刻と `inserted_at` を照合した。
- 12:10 JST の初回正常保存より前に締め切った42レースは導入前として別集計する。
- 15:29 JST 頃の時点で、導入後に締切済みの63レースのうち、52レースに V2 と V3 candidate-01 の2件が保存され、11レースは未保存。片方だけ保存されたレースと締切後保存は0件。
- 未保存11レースの現在の `bs_race_entries` には展示タイム・STが6艇分揃っていた。ただし現在値は後日も更新されるため、締切前に揃っていたという証拠にはならない。

## Vercel実行ログ

- 12:00 JST の実行は4レースで `trinity_scores` の NOT NULL 違反を記録した。12:10 JST の修正版から正常保存を開始した。
- 以後は10分ごとの実行で、保存対象に `no_exhibition`（6艇の展示タイム・ST不足）が毎回記録された。例：12:20 JST は8件の試行中3件保存、5件展示不足。
- 当時のログは見送りレースの識別子を残していないため、未保存11件すべての原因をレース単位で断定できない。`bs_race_entries.updated_at` は同日15:36 JST に一括更新された行があり、現在値の更新時刻から当時の展示ST取得時刻を復元できない。
- 10分間隔と締切3分前の保存限界の組合せでは、締切前に入力が揃っても再試行されない時間帯がある。

## 対応

- SHADOW Cron を2分間隔にして、保存可能な最後の3分に再試行できるようにする。
- 各Cron実行のログにレース識別子と試行結果を含める。今後の未保存は `no_exhibition`、`incomplete`、DBエラー等を個別に追える。
- 管理画面に、締切済み全レースを分母にした、導入後のV2/V3同一入力・締切前ペア保存率と未保存レース一覧を出す。これは入力準備率ではない。
- 片方だけ保存されたレースを後から異なる入力で補完せず、異常として表示する。
- この変更は予想ロジック、候補01の固定条件、公開TRINITY、過去スナップショットを変更しない。

## 再確認

新しい本番配置後、Cronの `attempts` を照合し、翌日の締切済みペア保存率と未保存理由を確認する。展示データが締切前に一度も揃わなかったレースは、後から再生成しない。
