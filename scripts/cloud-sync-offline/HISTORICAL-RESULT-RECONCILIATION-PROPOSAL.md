# Historical result reconciliation proposal — 2026-11-17 JST

Production read-only findings: all 600 missing event keys (Nov 13–16) have result_status=confirmed, race_status=finished, a trifecta and a trifecta payout in bs_race_results. Existing bs_apply_openapi_results updates event result_available/trifecta/payout when a result payload is supplied, but does not set event race_status=finished. Calling it with a second source payload would also update provenance and entry data; avoid that for historical recovery without a source comparison.

After a verified six-boat bootstrap in isolation, reconcile **only newly bootstrapped historical rows** by joining results on the full race key and requiring result_status=confirmed, race_status=finished, non-null trifecta result and payout. Copy result_available, race_status, trifecta and trifecta_payout only where event is still scheduled, data_source=BOATRACE_OPEN_API_BOOTSTRAP, no existing result/payout provenance and event's result fields are empty. Preserve original results, existing provenance and entry outcome columns. Use one transaction and assert exact input/result/event/entry counts before committing. Update of trifecta will invoke theory settlement trigger; compare theory table before and after and confirm no unexpected changes. A cancelled or partial result must fail the gate, not be coerced to finished.

This is a review design, not a production migration. Test a finished fixture, conflicting provenance, incomplete result and retry in isolation. Check if the result trigger has any further effects before implementation. Production backfill remains HOLD.
