# NEWS 結果記事の緊急対策（締切前の「結果確定」記事を防ぐ）

作成日：2026-10-13／ブランチ：`claude/news-result-guard`（main から作成。PHASE 2A の変更は含まない）

変更は、NEWS の結果記事（`bs:result:*`、見出し「○R の結果を更新」）の生成処理に限っている。本番DBへの書き込み、既存記事の更新・削除、外部同期処理の変更、デプロイはしていない。

## 1. 実装

### 判定（`lib/raceResultGuard.js`、純粋関数）

`checkRaceResultConfirmed()` は、次の条件をすべて満たすときだけ生成を許可する。1つでも欠けていたり矛盾していたりすれば生成しない（fail closed）。

1. レース日・場・R番号が正しい形式で、レース情報（bs_race_events）・確定結果（bs_race_results）・出走データ（bs_race_entries）のすべてで一致する。
2. 中止・不成立（race_cancel_code）でない。
3. 現在時刻が締切時刻から10分以上たっている。締切時刻が無い場合は生成しない。
4. 3連単の組番が3艇とも別の 1〜6 で、払戻が正の整数。
5. 確定状態：bs_race_results が `result_status = confirmed`（race_status があれば `finished`）で、3連単の組番と払戻が bs_race_events と一致する。
6. 確定着順：1〜3着がそれぞれ1艇ずつ存在し、3連単の組番と一致する。同着や着順の欠けがあれば生成しない。
7. `result_available` は判定に使わない。

`confirmedRacesForArticles()` は上の判定に加えて、同じレースの結果記事（`bs:result:日付:場:R`）が既にあれば除く。

### 収集処理（`lib/hatsuneNewsCollector.js`）

- 変更したのは、結果記事の候補を作る部分だけ（`collectResultCandidates()` を追加）。公式ニュース・明日の注目・高モーターの候補、`insertCandidates()` には手を入れていない。
- 判定に必要なデータは、レース情報・確定結果・出走データ・既存の結果記事の4つ。どれかの読み取りに失敗した場合や、取得件数が上限（1000件）に達した場合は例外にし、結果記事だけを作らない（他の候補はそのまま）。
- 記事にするレースは、確定条件を満たしたものの中から選ぶ（優勝戦・ドリーム戦を優先し、なければR番号が最大のもの。従来どおり）。
- 要約は「3連単X-X-X（払戻N円）で確定」とした。「結果が確定」だけの文は作らない。

## 2. テスト

`tests/news/race-result-guard.test.mjs`（10件）を追加した。既存の NEWS テストと合わせて50件すべて成功（`node --test tests/news/*.test.mjs`）。

| ケース | 結果 |
|---|---|
| 締切前で result_available=true（id 1848 と同じ 10:00 の状況・締切直後10分以内） | 生成しない |
| 締切後だが払戻が無い・0・組番が不正・確定結果と払戻が食い違う・確定結果の行が無い・確定状態でない | 生成しない |
| 払戻はあるが着順が無い・同着・着順が3連単と食い違う | 生成しない |
| 全データが揃った正常レース | 1件生成（要約に3連単と払戻） |
| 場・日付・R番号の不一致（レース情報・確定結果・出走データ、形式不正） | 生成しない |
| 中止・締切時刻なし | 生成しない |
| 重複（同じレースの結果記事が作成済み） | 生成しない |
| データ取得失敗（確定結果・既存記事の読み取りエラー、件数上限） | 例外 → 結果記事だけ作らない |

## 4. result_available を参照している NEWS 以外の機能（調査のみ・変更なし）

10/13 は、日中の同期で当日の全レースが `result_available = true` になっていた（14:30 時点で132件中、締切前67件も true）。この状態で影響を受ける箇所は次のとおり。

| 機能 | 参照のしかた | 早すぎる true の影響 | 確度 |
|---|---|---|---|
| 予想：三連単オッズの記録（`app/api/cron/elimination-odds-snapshots`、`lib/eliminationOddsSnapshot.js`） | `result_available = false` のレースだけ記録し、true なら保存しない | 締切前のオッズが記録されない。10/13 の記録は0件（10/12 は15件）。ただし普段から件数が少ないため、断定はできない | 中 |
| 予想：TRINITY の事前予測（DB関数 `trinity_shadow_guard`） | `result_available` が false でなければ、予測の保存を例外で拒否する | 締切前でも予測を保存できない。10/13 の15〜16時台は前日より少ない（32/18件、前日は40/24件） | 中 |
| 公式の中止検知（`lib/officialRaceCancellationSync.js`） | `result_available !== true` のレースだけ確認し、更新も `result_available = false` の行に限る | 中止・順延を検知・記録できず、中止レースが「結果あり」のまま残る可能性 | 高（コード上） |
| レース画面（`lib/boatstrikersPlatform.js` の `getRaceStatus`、`app/races/[courseCode]/[raceNo]/page.js`） | `result_available` が true なら、状態を「結果」・結果確定扱いにする | 締切前のレースが「結果」扱いになり、展示・発売中の表示や今後のレース一覧から外れる可能性。`app/lib/racesIndexLight.js` は確定結果テーブルを使うため影響しない | 高（コード上） |
| 選手ページ（`app/racers/[registrationNo]/page.js`） | 締切時刻が無い場合だけ「結果確定」を表示 | 限定的 | 低 |
| NEWS 候補の検証（`lib/newsCandidateVerifier.js`） | 締切前は必ず「予定」とし、締切後は true なら「確定」とする | 締切直後〜結果確定前に「確定」と判定し、X候補にされる可能性 | 中 |
| 結果集計：日次まとめ（`lib/dailyResultDigest.js`、23:10） | 全レースが true なら生成する | 生成の前提条件として機能していない。ただし払戻はその時点で入っていて、件数は今回の照合でほぼ一致 | 低〜中 |
| DATA LAB（`lib/dataLabSocialGenerator.js`、翌朝 06:20） | true のレースを集計する | 実行時刻には全レースが終わっているため、影響は小さい（決まり手コードの問題は別件） | 低 |
| X夜間候補（`lib/xNightCandidateSnapshot.js`）、DBビュー `v_bs_race_results_confirmed` | `result_available OR（3連単＋払戻＋締切5分後）` | 夜間の実行なら影響は小さいが、日中に使うと締切前のレースも確定扱いになる | 低 |
| 管理画面（AI候補、グレード、同期状況、一果分析）、ヘルスチェック | 表示・件数に使う | 締切前のレースが「結果あり」に数えられる | 低 |

`result_available` を立てている外部の同期処理を直すのが根本対策（このリポジトリの外のため、今回は変更していない）。上の各機能は、その修正まで影響を受け続ける。
