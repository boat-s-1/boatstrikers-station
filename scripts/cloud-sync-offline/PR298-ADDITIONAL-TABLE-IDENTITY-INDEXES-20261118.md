# PR298 — additional table index and identity inventory (2026-11-18)

All findings from SELECT-only production pg_catalog queries. **Current state only; not a dated historical genesis definition.**

## bs_race_result_entries

- `id bigint NOT NULL` is `GENERATED BY DEFAULT AS IDENTITY` (`pg_attribute.attidentity='d'`), despite `pg_attrdef` reporting no ordinary default expression.
- Owned sequence resolved by `pg_get_serial_sequence`: `public.bs_race_result_entries_id_seq`. Catalog sequence parameters observed: start 1, increment 1, min 1, max 9223372036854775807, cache 1. No sequence current value was accessed.
- Indexes:
  - `bs_race_result_entries_pkey`: unique btree `(id)`
  - `bs_race_result_entries_race_date_course_code_race_no_boat_n_key`: unique btree `(race_date, course_code, race_no, boat_no)`
  - `idx_bs_result_entries_race`: nonunique btree `(race_date, course_code, race_no)`

## racer_gender_master

- `racer_gender_master_pkey`: unique btree `(racer_id)`
- `racer_gender_master_gender_idx`: nonunique btree `(racer_gender)`

## Consequences

A reconstructed schema that declares `id bigint` without IDENTITY would not reproduce current insert semantics. Index and constraint recreation must avoid duplicate index creation (PK and UNIQUE constraints already generate backing indexes). The historical creation time and original definitions remain unknown; do **not** promote this current catalog snapshot into a migration genesis baseline without provenance.
