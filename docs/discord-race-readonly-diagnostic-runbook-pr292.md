# PR #292 — Discord実環境の読み取り専用診断 実行手順

## 現在の制約
- Vercel本番プロジェクト `boatstrikers-station` にはDiscord関連の環境変数名が登録されている（値・有効性は未検証）。
- GitHub ActionsのPRテストには本番Botトークンを渡さない。PRから本番シークレットを読ませない。
- Vercelの環境変数を復号してチャット、ログ、Issue、PRへ貼らない。
- 現時点では、診断スクリプトを**実Discordの認証済み実行環境で動かした証拠はない**。CIの23件PASSはモック／静的検証であり、実Discord接続成功を意味しない。

## 実行ゲート
1. 管理者が本番Botトークンを安全に参照できる、アクセス制御された実行環境を選定する（ローカル管理者PCまたは承認済みの手動専用ジョブ）。新規公開APIルートは作らない。
2. 実行前にスクリプト `scripts/discord-race-readonly-diagnostic.mjs` がGETのみを実行することをレビューする。
3. 管理者が実行環境へ `DISCORD_BOT_TOKEN` と `DISCORD_GUILD_ID` を**環境変数として安全に設定**する。チャット・CLI引数・GitHub Actionsログ・PR本文へ値を表示しない。
4. 手動で `node scripts/discord-race-readonly-diagnostic.mjs` を実行する。必要に応じて `DISCORD_DIAGNOSTIC_THREAD_ID` に照合対象のスレッドIDを設定する。
5. 出力されるチェック名・件数・真偽値と終了コードだけを保存する。秘密値、ユーザー情報、投稿本文は保存しない。
6. HTTP 401/403、チャンネル数0/複数、親ID不一致、アーカイブ済み、取得失敗は**HOLD**。自動修正・投稿・再送はしない。

## 診断の範囲と不足
- 確認対象：ギルドのチャンネル一覧、レース実況チャンネルの一意性、アクティブスレッド一覧、任意の指定スレッドのID・親ID・種別・archive状態。
- 確認**対象外**：スレッド内の投稿本文、メッセージID照合、Webhook作成可否、書き込み権限、実投稿、DB状態更新、Cron有効化。
- 投稿の重複／欠落を実際に照合するには、別途承認済みの読み取り専用メッセージ照合機構とDBの対象レースIDが必要。現行スクリプトだけで本番導入GOにはしない。

## 中止・復旧
- 診断はGETのみのため投稿のロールバックは不要。失敗したら終了し、原因・時刻・HTTPステータスを秘密値なしで記録する。
- Botトークンがログ等に露出した場合は診断を停止し、管理者がDiscord Developer Portalでトークン失効・再発行を判断する。
- 本番のDiscordレース実況Cronは無効のまま。Supabase本番マイグレーション・Vercel本番デプロイ・Discord書き込みは実施しない。
