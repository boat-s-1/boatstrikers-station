# AI司令塔 — 期限付きリースの隔離DB検証（2026-11-17）

## 実装した検証
一時的なPostgreSQLサービスに `agent_monitor.lease_fencing_ci` を作り、以下を実際のSQLで確認する。
1. 最初の担当がリースを取得し、epoch=1となる。
2. 有効期限を過ぎたら別担当が取得し、epoch=2となる。
3. 古い担当（epoch=1）は、新担当のリースを解除できない。
4. 現担当（epoch=2）は更新・解除できる。

## 安全境界
- 本番DBにリーステーブルを作成しない。外部通知も送信しない。
- `127.0.0.1` / `agent_controller_ci` 以外への接続を拒否。
- これはリース所有権と世代番号の単体的なDB検証であり、実ワーカーの停止・再起動、ネットワーク分断、外部サービスへの送信競合を検証したものではない。
- 特に、期限切れの古いワーカーが外部通知を送信しない保証には、送信直前の再検証、受信側の冪等性、または外部サービスでのフェンシング対応が必要。
