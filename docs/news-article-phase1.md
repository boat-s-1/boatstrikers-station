# BoatStrikers NEWS 記事品質改善 PHASE 1（試作と検証）

作成日：2026-10-12／ブランチ：`claude/elegant-maxwell-ha2awt`

## 1. この PHASE でやったこと・やっていないこと

- 新しい記事生成ロジック（NEWS FACT／DATA CHECK／EDITOR'S VIEW／品質チェック）を **純粋関数として試作** し、本番の公開記事で新旧比較した。
- 本番DBは **読み取り（SELECT）だけ**。記事の更新・削除、DBトリガー、cron・収集処理、既存の NEWS 画面は **変更していない**。新しいモジュールはどの画面・APIからも呼ばれていない。
- main への変更・デプロイはしていない。

## 2. 実装したもの（`lib/newsArticle/`）

| ファイル | 役割 |
|---|---|
| `sourceText.js` | 要約の掃除。出典サイトの宣伝後置き（「- 日刊スポーツ新聞社のニュースサイト…」）、URL、時刻、`…` で途中切れの文、閉じていない談話、収集時の定型文（「女子ボートレース関連ニュースです」「元記事の内容を転載せず」等）を除く。開催場の判定、選手名の異体字の同一視（滝/瀧、斉/齋、高/髙 など）。 |
| `newsFacts.js` | **NEWS FACT**。見出し・要約から事実をスロット（選手・年齢/支部・場・R・優勝戦・枠・コース・ST・決まり手・着順・記録・返還額・売上・談話）として取り出し、BoatStrikers の文で組み立て直す。取り出せないものは書かない。「通算17度目Ｖへ」「初勝利を目指す」「12R4着以上で届く」のような目標・条件は事実にしない。他の選手が主語の文（「3コースの大神康司は…」）の数値は主役に混ぜない。着順は文節単位で読み、「2着」を1着と誤読しない。決まり手だけの文は1着とみなさない。 |
| `dataCheck.js` | **DATA CHECK**。場・公開日の6日前〜公開日の出走表で選手名を照合し、**登録番号が1人に決まった場合だけ**採用。記事の**公開時点で締切から20分以上たったレースだけ**使う（公開後の結果を混ぜない）。今節の着順・平均ST・1コース成績・モーター、対象レースの号艇・コース・ST・着順・決まり手・3連単を整理。記事の記載（R・枠・コース・ST・着順・決まり手・F・連勝）を DB と照合し「一致／不一致／未確認」を返す。**優勝戦はレース種別 `race_kind_code=0021`（RACE画面・日次まとめと同じ判定）で確認できた場合だけ**、**グレードは `bs_grade_race_events` で確認できた場合だけ**一致とし、それ以外は DATA CHECK に書かない。BS DATA は結果まとめ（`bs_daily_result_digests`）、1レース結果、モーターを照合。照合できない場合は欄ごと省略し理由だけ返す。 |
| `editorView.js` | **EDITOR'S VIEW**。NEWS FACT・DATA CHECK の数字だけで短いコメントを作る。初音＝女子関連の根拠がある記事（一覧と同じ判定、名前から性別は推測しない）で今節3走以上、キイナ＝3連単1万円以上または20番人気以上、または日次まとめの万舟、一果＝1コースの成績・ST。どれにも材料が無ければ省略。予想・評価語は使わない。 |
| `qualityCheck.js` | 品質チェック。出典名・URL、収集定型文、女子以外の記事への「女子」混入、見出し・要約との25文字超の連続一致（談話の「」内は除く）、NEWS FACT の出典にない数値、EDITOR'S VIEW の材料にない数値、予想・埋め草表現（期待／確認したい／明らかになっていない／見逃せない 等）、DBで確認できない優勝戦・グレードの記載、重複文、DBとの不一致を検出する。 |
| `draft.js` | 上記を組み立て、`ready`（そのまま使える）／`needs_review`（品質エラーまたはDBと不一致）／`insufficient`（材料不足で本文を作らない）を返す。出典名は本文に入れず `sourceNote` に分ける。 |
| `raceDataLoader.js` | DATA CHECK 用のレースデータ取得（`select` のみ）。PHASE 1 では未使用（検証は Supabase の読み取りクエリで取得したデータで実施）。 |

テスト：`tests/news/news-article-draft.test.mjs`（14件）を追加。NEWS 関連の既存テストと合わせて **54件すべて成功**（`node --test tests/news/news-article-draft.test.mjs tests/news/news-taxonomy.test.mjs tests/news/news-importance.test.mjs`）。ローダーのテストでは、偽の DB クライアントで insert/update/upsert/delete/rpc が呼ばれないことを確認。

- `needs_review` 1件（id 1579「3日目10Rから3連勝」）は検証用データの取得範囲が 10/6 からで 10/5 以前のレースが無いことによるもので、本番の取得範囲なら解消する見込み。
